# Generic-owner NativeAOT measurement closure — 2026-08-13

## Outcome

The exact compiler-record-driven generic-owner measurement corpus now links
and executes as a real Windows x64 NativeAOT application. JIT, ReadyToRun,
full trimming, and NativeAOT all execute workload version 2 with checksum
`2027804433`. `nativeAotProven` is true only after the native executable has

This closes the bounded corpus's missing NativeAOT link/run evidence. It does

measurements.

## Measurement race found and removed

The first native publication and execution succeeded, but the tool rejected
the result because the zero-iteration NativeAOT process exited before the
2-ms working-set polling loop obtained a positive sample. Treating that as
zero or dropping the counter would have weakened the recorded gate.

Workload version 2 therefore adds an instrumentation-only stdin handshake.
After writing and flushing the complete measurement protocol, the child waits
for `release`; the parent stops its wall clock at the protocol line, reads the
live process's real `PeakWorkingSet64`, and then releases it. The hold is after
the internally timed workload and outside the parent wall time. All four modes
use the same handshake. Version-1 bundles are rejected by the updated tool.
