# Preserve array-factory physical results under object destinations

This correction starts from `56ea8544fe`. Current integration belongs in
[`../../STATUS.md`](../../STATUS.md), and the durable rule is recorded in the
[star-array decision](../decisions/star-projected-arrays.md).

## Reproduced cause

The source-built rehearsal census still contains the same 234 error lines as
the earlier census. Among them, the explicit array iterator intrinsic rejects
its canonical Runtime `Iterator` reference when a semantic destination already
expects `object`. This is not permission to construct `Iterator<object>`.

A separate `lib`/`main` fixture, `arrayIteratorObjectResult.kt`, isolates seven
compile failures on the reviewed base: star/opaque/projected iterator results,
an opaque exact-vector iterator, and star/exact/primitive iterable results.
The primitive iterator control does not report that failure.

Ordinary expression codegen normally emits a reference at its actual type and
then widens it to `object` without an instruction. In a semantic operation the
object destination may already be authoritative, so codegen intentionally does
not remap the broad logical interface to a fabricated natural construction.
The intrinsic then sees that destination directly. Its exact-equality guards
incorrectly reject a valid widening of its fixed factory result.

## Correction and boundaries

Three canonical Iterator/Iterable result checks now use the existing
instruction-free CLR assignability relation. The factory MethodDef references,
return signatures, receiver mapping, array storage, and factory bodies are
unchanged. This covers both exact and erased vector factories. Primitive
iterator factories retain their exact primitive-iterator class contracts.

No additional cast, boxing instruction, proxy, or wrapper is introduced. A
canonical factory result is not assignable to an invented natural generic
interface; those typed destinations remain outside this proof. Kotlin source
and KLIB logical return types are unchanged. The correction changes shared
intrinsic code, so it uses the full production target gate rather than claiming
production-inert rehearsal admission.

The Common contract remains ordinary array iteration and reference widening.
The existing JVM array iterator intrinsic calls its fixed helper and the JS
primitive-container lowering redirects to its iterator helper; neither copies
the array algorithm into callers. This change preserves the same existing
Kotlin/.NET helper boundary. Common, Runtime, and Stdlib sources are untouched.
