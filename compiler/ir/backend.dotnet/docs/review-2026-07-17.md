# Kotlin/.NET (CIL) Backend — Final Consolidated Architectural Review

**Subject:** experimental Kotlin/.NET backend, branch `dotnet` @ `8dd89907d`, under
`compiler/ir/backend.dotnet/` + `compiler/cli/cli-dotnet/`.
**Question:** is this architecture on a path to an official Kotlin target?
**Evidence base:** ten dimension reviews, five adversarial red-team analyses, one adversarial
verification pass over every finding, and one completeness critique. All claims below carry
file:line citations from the branch; every claim is tagged **[fact]**, **[interpretation]**,
**[documented-decision]**, or **[recommendation]**.

**Classifications used (exactly one per issue):** `correct-direction` · `correct-temporary` ·
`reasonable-divergence` · `questionable` · `architecturally-wrong` · `deferred-must-record`.

## 1. The one cross-cutting finding: the evidence floor

**Statement [fact]:** every decisive validation claim in the design law rests on evidence that is
not in the repository. All probe series cited by AGENTS.md (133 mentions), HANDOVER.md (57), and
all 12 ADRs — `runtimeprobe_s1`, `boxprobe_s1-7`, `callableabi_s2`, `exceptionabi_s1-4`,
`netstandard_s1`, every Roslyn/C# consumer run, every .NET Framework 4.8 execution, all four
cross-runtime pairings, all benchmarks — live only under git-ignored `build/probes/`
(`.gitignore:24`). Committed automated execution is CoreCLR-only via `dotnet exec`
(`AbstractDotNetIlTextTest.kt:99-123`, `DotNetLibraryIntegrationTest.kt:1110`). There are zero
committed `.cs` files (`git ls-files "*.cs"` empty), zero Framework-CLR executions (the
`netframework` integration tests compile and grep IL only, `DotNetLibraryIntegrationTest.kt:811-835`),
zero version-skew fixtures (the `ABI_VERSION="2"` hard-reject at
`DotNetFrontendPipelinePhase.kt:209-216` is untested), and the sole mangler-drift pin is one
hardcoded key (`DotNetLibraryIntegrationTest.kt:1040`).

This consolidates placement P2 (REVISED to deferred-must-record/high), testing F1/F4/F6 (all
CONFIRMED), abi F8 (CONFIRMED), and runtime-floor attack 3 (HOLDS). It is reported once here and
referenced elsewhere, rather than re-counted per dimension.

- **Invariant at stake:** an ABI floor and an interop contract are testable propositions; a claim
  only a prior session can vouch for is a memory, not an invariant.
- **CLR constraint:** Framework and CoreCLR genuinely diverge in observable ways the backend
  itself documents (`-0.0` formatting, AGENTS.md:2033-2035; SAC; ilasm flavors) — the floor cannot
  be inferred from CoreCLR passes.
- **Mature-target comparison:** JVM runs a real JDK matrix in CI; Native runs per-target grids;
  Wasm runs under real engines. No mature target validates its execution floor with
  engineer-local notes. Kotlin/JVM commits javac-compiled Java interop tests in-suite — the
  foreign compiler is part of the test matrix by established practice.
- **Alternatives:** commit toolchain-gated lanes (the box suite already demonstrates the
  skip-if-unprovisioned pattern): a Framework-execution box lane; a Roslyn C# consumer
  integration test (csc ships in the already-provisioned SDK); a cross-assembler pairing test; a
  doctored-manifest skew CLI golden (machinery exists, `DotNetLibraryIntegrationTest.kt:1047-1060`);
  an assemble-all-goldens lane; commit probe *scripts* as replayable sources.
- **Long-term consequence if unaddressed:** the ABI freezes on unfalsifiable lore; F1/F2-class
  linkage bugs (see §D7) stay latent — the verifier confirmed the missing skew suite is exactly
  why the vararg-key break landed unnoticed.
- **Classification: deferred-must-record. Significance: high — the highest-leverage single
  workstream on the branch.** This is deliberate POC practice (HANDOVER.md:1105-1106 keeps probes
  out of the repo intentionally; ADRs disclaim commitment, stdlib ADR:7-8), so it is a recorded
  practice with an unrecorded conversion obligation, not misconduct — but officialization-grade it
  is not. [interpretation + recommendation]

## 2. Dimension reviews

### D1 — Compiler architecture & target integration

Overall: the target integrates with the modern K2 architecture more faithfully than early
prototypes usually do — phased `AbstractCliPipeline` (`K2DotNetCompiler` →
`DotNetCliPipeline.createCompoundPhase`, mirroring JS/Wasm/Native product selection),
`CommonBackendContext` implemented honestly, `PhaseEngine`/`createModulePhases` so phase
dump/validate tooling works for free, idiomatic `DotNetPlatform` registration
(`WasmPlatforms` idiom, ABI dump updated). [fact]

**D1.1 Frontend bootstrap = the metadata compiler wearing a .NET badge — correct-temporary (high). CONFIRMED.**
- *Statement:* the frontend uses `EnvironmentConfigFiles.METADATA_CONFIG_FILES` +
  `prepareMetadataSessions` (`DotNetFrontendPipelinePhase.kt:61-65,90-102,117-129`), fir2ir uses
  `forKlibCompilation` + `DefaultBuiltIns.Instance` + no actual extractors
  (`DotNetFir2IrPipelinePhase.kt:23-36`), and stdlib resolution comes from a 3-file, 363-line
  injected fake stdlib (`DotNetStdlibSource.kt`) or an installed metadata-KLIB pair. [fact]
- *Invariant:* the frontend a target ships defines its resolution semantics forever (default
  imports, checkers, actualization); IL-level ABI pinning is worthless if the accepted language
  surface shifts when the session type changes.
- *CLR constraint:* none — pure compiler architecture.
- *Alternatives:* build `FirDotNetSessionFactory` against the metadata-KLIB provider now (the
  KLIB-loading half already exists) vs. keep metadata sessions until the serialized stdlib lands.
- *Consequence:* the session-factory switch changes frontend behavior observable in every golden;
  the later it lands, the harder intended vs. accidental changes are to separate. There is **no
  .NET checker registration point today**, which is why 323 shape gates live in the backend as
  warnings; and expect/actual has no path (the durable stdlib plan *requires* actualization the
  metadata session cannot provide — verifier: no ADR/AGENTS/HANDOVER text records the migration;
  stdlib ADR:109-110 records only the endpoint). [interpretation]
- *Mature-target comparison:* JS/Wasm/Native register platform session factories with checkers,
  default imports, and real builtins providers; `DefaultBuiltIns.Instance` in fir2ir is itself
  NOT a deviation (JVM/JS pass it too).
- **DefaultImportsProvider hook** (`FirMetadataSessionFactory.kt:307-311`): a 10-line target hack
  bolted *beside*, not through, `processPlatformsWithContext` — acceptable only because D1.1 is
  temporary; must not be upstreamed as-is. correct-temporary. [fact]

**D1.2 Diagnostics model — deferred-must-record (high). CONFIRMED.**
`DotNetBackend.kt:22-25` opts into raw `MessageCollector`; the constructed
`KtDiagnosticReporterWithImplicitIrBasedContext` (`DotNetBackendContext.kt:56-59`) is used
nowhere; all 28 report sites are position-less; evictions are WARNING
(`DotNetIlEmitter.kt:1102-1116`). None of the 12 ADRs covers diagnostics; AGENTS.md:21-24 records
eviction as a design rule with no sunset. Invariant: a compilation that exits 0 contains every
declaration the frontend accepted; no mature backend drops declarations from a successful
artifact. Endpoint: FIR checkers as errors with locations (the 323 `dotNetUnsupported` messages
are already a user-grade checklist), `dotNetUnsupported` demoted to ICE. See D2.1 for the
unified eviction verdict. [fact + recommendation]

**D1.3 Shared-code diffs — correct-direction (3 IR fixes) / correct-temporary (1 hook). CONFIRMED.**
Exactly four load-bearing shared edits since base `995cf26a0` (verified by diff):
`ArrayConstructorLowering.kt` (evaluation-order fixes: size evaluated before `Nothing`-typed
initializer; invokable evaluated before allocation; guarded INC→`plus(1)` fallback),
`FlattenStringConcatenationLowering.kt` (open + `isFoldableConstant` hook, behavior-preserving),
`IrInlineUtils.kt` (latent CCE fix), and the session hook. The two genuine cross-backend
correctness fixes must be extracted and upstreamed as separate tested commits per
`.ai/commit-guidelines.md` (precedent: `735352c17`); the evaluation-order fix currently rides
inside `fb8b20d0a "[DotNet] Support concrete array initializers"` (placement P7, CONFIRMED
questionable/low). [fact + recommendation]

**D1.4 Platform identity & KLIB kind — deferred-must-record (medium). REVISED.**
`BuiltInsPlatform` has no DOTNET member (`BuiltInsPlatform.kt:8-9`); produced klibs claim COMMON,
fenced only by `dotnet_*` custom manifest properties generic tooling ignores
(`DotNetLibraryMetadataPipelinePhase.kt:149-151`). The platform-marker deferral IS recorded
(stdlib ADR:302 with COMMON-fence rationale at :86-88) — the residue is unrecorded: KMP
membership (`CommonPlatforms`/`KotlinPlatformType`/KGP), and one sentence stating the target is
deliberately K2-only. A real `BuiltInsPlatform` entry is an upstream change with lead time —
request early. [fact + recommendation]

**D1.5 `allowKotlinPackage` split across two disagreeing mechanisms — questionable (low-medium). CONFIRMED.**
The analysis flag (what `FirKotlinPackageChecker.kt:23` reads) is set iff `!noStdlib`
(`K2DotNetCompilerArgumentsConfigurator.kt:14-16`); the CLI key is keyed on
`usesBootstrapStdlibSources` (`DotNetConfigurationPipelinePhase.kt:197-202`) but feeds only
`checkKotlinPackageUsage`, which the pipeline never calls. Net: with an installed stdlib pair,
user sources may still declare `package kotlin` — and the stdlib ADR:186-187 *promises* the
opposite. Fix: compute once, key both. [fact]

Other D1 findings: CLI conformance exact with minor warts (`JvmClasspathRoot` naming lie-in-waiting;
tmpdir race in injected-stdlib path; dense output-path logic) — correct-direction (medium);
test-infra registration idiomatic but the suite lives inside `compiler/fir/fir2ir` (a frontend
module hosting a backend's codegen suite) and must move to a dotnet-owned module —
correct-temporary (medium-low); backend context/lowering reuse genuinely thin (13–77-line
subclasses; best-documented phase list in the repo) — correct-direction. [fact]

### D2 — IL codegen layer

**D2.1 Eviction-to-fixpoint (unified verdict for the branch's most-cited issue) — deferred-must-record (high). REVISED from architecturally-wrong.**
- *Statement:* unsupported IR throws `dotNetUnsupported` (323 sites); the emitter evicts to a
  fixpoint (`DotNetIlEmitter.kt:812-927`), warns per declaration (`:1101-1119`), errors only when
  the entry point is hit (`:1142-1148`); library mode inherits the policy unchanged
  (`DotNetBackend.kt:154-171`) — the FIR-serialized KLIB stays complete while the physical index
  records only survivors (`DotNetLibraryAbi.kt:360`), so a consumer resolves declarations the DLL
  lacks and the *consumer's* caller is then evicted (`DotNetIlExpressionCodegen.kt:866-867`). [fact]
- *Invariant:* what a compiler emits equals what it accepted; for a library, the logical (KLIB)
  and physical (DLL) surfaces must be the same set or the build must fail.
- *CLR constraint:* none — pure compiler policy.
- *Why not architecturally-wrong (verifier):* the mechanism is a recorded design rule with an
  acknowledged frontend-checker exit on a POC branch; consumer outcome is a loud index miss,
  never silent wrongness, and the producer warns (abi F4 REVISED accordingly). The eviction
  *granularity* rules are individually justified and golden-pinned; the fixpoint is sound (no
  stale reference survives).
- *Alternatives:* (1) endpoint — FIR checkers as located errors, `dotNetUnsupported` → ICE;
  (2) immediate and cheap — **any eviction is an error in `-Xdotnet-produce-library` /
  `-produce-stdlib` modes** (exports already implement exactly this severity split,
  `DotNetIlEmitter.kt:929-932`); (3) assert KLIB-index/metadata parity at packaging.
- *Consequence:* silent transitive API shrinkage across module hops in a library ecosystem;
  plus warning-channel fragility — the diagnostics are locationless (the `IrDeclaration` is in
  hand at every site), and **zero committed assertions cover any skip warning** (grep across all
  testData; testing F7 CONFIRMED questionable/medium; codegen-2 CONFIRMED questionable/medium).
- *Mature-target comparison:* JVM ICEs on unhandled IR; unsupported constructs are frontend
  errors everywhere; no mature backend ships subset artifacts.
- **[recommendation]** Record the model + sunset in an ADR now; land alternative (2) immediately;
  pin one eviction warning per granularity class in CLI goldens.

**D2.2 Textual IL + external ILAsm — correct-temporary (medium). [documented-decision]**
The ADR (`draft-adr-il-assembly-pipeline.md:27-56`) is honest: text+ILAsm for the POC, a
structured compiler-owned CIL/metadata model before productionization, then a JVM-hosted direct
PE writer; migration triggers and acceptance criteria recorded (`:79-99`). One consequence must
be stated plainly: type equality, clash gates, assignability dedup, and the KLIB physical index
all key on rendered strings (`DotNetIlType.kt:176-178,239-243`; `DotNetIlEmitter.kt:661-710`), so
the structured model is a rewrite of identity plumbing, not a writer swap. Costs of ILAsm
(non-reproducible PE bytes, fresh MVID) are on the productionization list. [fact]

**D2.3 AssemblyRef/packaging by substring over rendered IL — questionable (medium). CONFIRMED.**
`.assembly extern` rows, the stdlib-required error, and DLL copying are all driven by
`"[<name>]" in ilText` (`DotNetIlEmitter.kt:1213-1224`; `DotNetBackend.kt:179,208-230`) while
`toIlStringLiteral` escapes neither `[` nor `]` (`DotNetIlCodegenSupport.kt:917-934`) — so
`println("[Kotlin.Stdlib]")` without a bound stdlib is a hard error and `"[MyLib]"` triggers
spurious externs/copies. False-positive-only family; unpinned. Cheap fix: record referenced
assemblies in a side set at render points. [fact]

**D2.4 No IL verifier lane; depth-only stack tracker with one unchecked merge — questionable (high). CONFIRMED.**
The tracker enforces real ECMA-335 region rules with probe citations (empty-stack `.try` entry,
`leave`/`endfinally` discipline, handler depth resets), but `emitLabel` adopts a recorded branch
depth over a conflicting fall-through depth with no error (`DotNetIlMethodContext.kt:176-180`;
branch-vs-branch IS checked at :161-164); pops/pushes are caller-declared; and grep finds no
ilverify/peverify anywhere. On a platform that **executes unverified IL** (unlike the JVM's
load-time verifier), the compensating control is box coverage — which the docs themselves mandate
because failure families "assemble CLEAN" (HANDOVER.md:1107-1114; `DotNetIlType.kt:117-123`) and
which SAC hosts skip. An offline `dotnet-ilverify` lane over box artifacts + runtime DLLs is the
single highest-value cheap addition to this layer; also fix the two-line merge check. [fact + recommendation]

D2 positives (correct-direction, verified): single widening-coercion authority mirroring JVM
StackValue (`DotNetIlExpressionCodegen.kt:196-233,1990-2022`); deterministic, reviewable goldens;
intrinsic registry in the JVM shape with rejection intrinsics — though the registry currently
*is* the stdlib (2.8k lines) and semantics parked there version with the compiler, not the
library; drain plan recorded (correct-temporary, medium).

### D3 — Core value semantics (Any, equality, nullability, arrays, rendering)

The strongest dimension. The three foundational commitments are argued against real
alternatives, probe-verified at instruction level, and runtime-pinned:

- **`System.Object` as physical `Any` + runtime-normalized Intrinsics — correct-direction (high).**
  `AreEqual`/`HashCode`/`StringValueOf` restore Kotlin semantics against CLR defaults exactly
  where they diverge: canonical-bits boxed-Double equality and hash (Java formula), NaN
  canonicalization, Boolean 1231/1237, Char numeric hash, lowercase Boolean text, culture-pinned
  integer text (`DotNetRuntimeLibraryHelpers.kt:1680-1770,2470-2483`); typed and boxed positions
  print identically, and Double constants are excluded from folding so constants cannot diverge
  from runtime (`DotNetIlExpressionCodegen.kt:621-630`). Pinned by `box/anyMembers.kt`.
  Single most load-bearing early commitment; the correct one. [fact + documented-decision]
- **Hybrid `Nullable<T>` — correct-direction / reasonable-divergence from JVM blanket boxing.**
  Concrete `Int?` is `System.Nullable<int32>` in exact positions, boxed-or-null at `Any?`
  (CLR box-collapse); `GetValueOrDefault`-never-`get_Value` so the wrong exception identity can
  never surface (`DotNetIlType.kt:136-143`); mandatory home-address spill kills the fatal
  0x80131506 poison shape at one chokepoint; Roslyn lifted equality with IEEE `Double?` matching
  JVM's two-regime split exactly. C# sees `int?` where Kotlin wrote `Int?` — the single most
  important interop property of a CLR target. [fact + documented-decision]
- **Arrays — correct-direction.** Invariance never erased into CLR covariance; store-check
  backstop parity with JVM `ArrayStoreException`; negative-size guarded with a compiler-owned
  `Kotlin.NegativeArraySizeException` (the CLR's raw `OverflowException` would be the wrong
  identity); array `==`/`===` reference-`ceq` parity. [fact]

Open items (all of one species: safe today only because the shapes are **rejected loudly**, and
each must be written down before ABI freeze because each changes C#-visible surface the day it
lands):

| Issue | Classification | Significance |
|---|---|---|
| `Int?`→`Int` covariant override whole-class rejection; bridge design (wrap-and-delegate, machinery exists in `DotNetGenericInterfaceBridgeLowering`) needs an ADR before export ABI stabilizes (`DotNetIlEmitter.kt:1753-1796`; ECMA II.15.4.2.3) | correct-temporary | high |
| Generic `T?` totally rejected (`DotNetIlCodegenSupport.kt:613-618`); zero of 12 ADRs discusses it; box-to-object is the only coherent endgame (see red-team §4.3) and gates the stdlib's next ring (`Map.get(): V?`) | deferred-must-record | high |
| String hashing: `Intrinsics.HashCode` falls to virtual `GetHashCode` for String (`DotNetRuntimeLibraryHelpers.kt:1766-1769`) — .NET would be the only target with randomized per-process string hashes, while data objects bake host-JVM `FqName.hashCode()` constants (any-foundation ADR:159); no recorded policy; trivial at the single choke point today | deferred-must-record | medium |
| Double digit generation: identical IL prints 17-digit Framework `"R"` vs shortest-round-trip CoreCLR digits (`DotNetRuntimeLibraryHelpers.kt:48-63` KDoc documents only the Framework half); committed execution cannot catch a Framework regression (§1) | deferred-must-record | medium |
| No runtime null-guards at exported boundary — merged into I-1, §D8 | questionable | high |
| `Array<Int>`/`IntArray` `int32[]` identity collision (`DotNetIlCodegenSupport.kt:457-458`): no boxed-Int32 reference type exists on the CLR, every candidate changes source compat or interop; no ADR, no named mechanism — the one representation problem with **no clean endgame**, confront on paper early | deferred-must-record | high |
| `===` on nullable primitives rejected (more principled than JVM's arbitrary answer, but a compile failure for warning-level-legal Kotlin; graduate to frontend diagnostic) | reasonable-divergence | low |

Also verified correct: `Nothing` carrier (private-ctor sealed class + shared
`KotlinNothingValueException` guard), Unit (`void` + `pop` + INSTANCE at erased boundary),
generic-data-class private erased-equality view (zero ABI exposure; best ADR in the set),
`T : Any` constraint deferral (both halves argued). [fact]

### D4 — Callables, references, closures

**D4.1 Erased non-generic `Kotlin.Function0..3` as the sole identity ABI — correct-direction (high). CONFIRMED.**
- *Statement:* callable storage is non-generic `FunctionN { object Invoke(object...) }`; every
  legal variance conversion — including primitive-result and open-`T` — is an instruction-free
  reference copy preserving `===` (pinned across seven distinct conversions in
  `box/callableObjects.kt:114-195`).
- *Invariant:* Kotlin function types are variant over value types; conversions must not allocate
  or change identity. *CLR constraint:* ECMA-335 generic variance is reference-only, and
  `Func`/`Action` split Unit into a separate family — any generic canonical form needs
  identity-breaking adapters exactly where Kotlin exercises variance hardest.
- *Alternatives rejected in the ADR (L43-72):* `Func`/`Action` (foreign ownership + variance
  holes), generic Kotlin interfaces (same hole), hybrid per-instantiation (dual ABI + allocating
  conversions). Costs recorded honestly (boxing at the universal boundary; function-type-only
  overload clashes; Kotlin metadata mandatory cross-module, ADR:406-414).
- *Mature-target comparison:* deliberately reproduces what JVM erasure gives for free; the
  callable family and the split-interface family follow one doctrine (a coherence signal).
- Execution capabilities (`ExactFunctionN`, `TypedArgumentsFunction1-2`) are `isinst`-guarded and
  genuinely optional — misses fall back, old/new objects and call sites interoperate; the
  provenance second probe was verified sound (immutable-value walk, widening-only coercions,
  evaluation order preserved). correct-direction (medium). [fact]

**D4.2 Function-reference equality id is observer-dependent — questionable (high). REVISED; red-team A2 HOLDS (serious).**
Reconciled mechanism (per the verifier, superseding the dimension review's version): the id is
`"signature:" + IdSignature.toString()` when a signature exists, else
`"local:file:offsets:mangle"` (`DotNetCallableReferenceLowering.kt:371-381`) — and **the
signature arm has never executed** (zero `signature:` hits in all goldens; external/deserialized
targets render `local:<unknown>:-1:-1:...`, `callableCaptures.txt:192`; source symbols carry no
IdSignatures, AGENTS.md:1209-1210). Cross-module `::f == ::f` therefore returns false; the id
has no module component (theoretical false positives); both arms are unpinned compiler-internal
renderings; the ADR (L152-158) presents a never-executed arm as solved. The fix exists unused:
`DotNetLibraryAbi.kt:179-190` computes LEGACY-rendered public signatures on demand. Pre-freeze
defect, not wrong architecture — but the id format freezes the day the first cross-module
reference ships. [fact]

**D4.3 Arity 0..3 cap; BigArity and suspend — correct-temporary + deferred-must-record (medium). CONFIRMED.**
Arities 4..22 are mechanically additive; **>22 cannot follow the ADR's "same shape" clause**
(ADR:118-119) — the variadic carrier interacts with the equality-ABI arity field and export
gates, and no BigArity design exists anywhere (grep: zero). Suspend is structurally pre-reserved
(flag bits 0/2, arity+1, `DotNetCallableReferenceLowering.kt:383-392`) but the
`SuspendFunctionN` marker family — which must be born with the first shipped suspend callable,
since objects emitted without it can never gain it retroactively — is unwritten. [fact]

Other D4 verdicts: structural reference equality/hash/rendering = Native model, JVM-observable
parity everywhere tests reach (correct-direction, medium; defect confined to D4.2);
`MutableRef<T>` single reified capture cell — better than the JVM's erasure-artifact `Ref` family,
no boxing for captured primitives (reasonable-divergence, positive); property references as
erased KPropertyN wrappers consuming the callable extension rather than forking it
(correct-direction); KFunction name-only floor honest, with two recording gaps
(KFunction-arity overload collapse needs a negative pin; `is KFunctionN` rule)
(correct-temporary); INSTANCE caching per JVM precedent with one unpinned generic-owner edge
(correct-direction, low); TypedArgumentsFunction1/2 — correct-temporary (medium), with blocking
promotion-gate obligations: commit the benchmarks, regularize or demote the 1-2/non-Unit
asymmetry, record probe order as policy (see also red-team §4.4 A3). [fact + recommendation]

### D7 — ABI coherence & evolvability

The model — metadata-only KLIB + sibling DLL, keyed by `"C:"/"F:" +

**D7.1 Keys computed from lowered IR — architecturally-wrong (high). CONFIRMED — the branch's one standing architecture defect.**
- *Statement:* the producer computes index keys post-lowering (`DotNetIlEmitter.kt:1233`);
  `DotNetVarargLowering.kt:92` mutates `parameter.type` to invariant `Array`; the mangler hashes

  every public `fun f(vararg xs: String)` is recorded under a key **no consumer can compute**.
  The consumer's caller is then evicted with a warning misattributed to the consumer. [fact]
- *Invariant:* producer and consumer must derive the logical key from the same declaration shape —
  the metadata shape, pre-lowering. *CLR constraint:* none; pipeline ordering only.
- *Contradicts recorded design* ("signatures remain metadata-derived", library ADR:117-118) —
  not recorded deferred work. No cross-module vararg test exists (§1).
- *Alternatives:* compute keys for all exported declarations right after fir2ir, keyed by symbol;
  emitter intersects survivors with the precomputed map (minimal, preserves survivors-only
  indexing). *Consequence if unfixed:* every future shape-mutating lowering (default stubs,
  bridges, receiver rewrites) silently severs linkage. *Mature comparison:* JS/Native
  compute/serialize signatures at the klib boundary, before lowerings.

### 4.3 Hybrid nullability

**Held under attack (this model survived the most attacks of any area):** the lifted-equality
IL truth table including the `(none, some(0.0))` corner; the boxed `AreEqual` path with NaN
canonicalization (attack on `-0.0`/NaN **REFUTED** — exact modern-JVM parity); the
two-spellings-one-signature attack (**NEUTRALIZED** — representation is a pure function of the
declared Kotlin type per position); `get_Value` leak, unspilled receiver, `Nothing?` operands,
cross-primitive `==` (all REFUTED — correctly discarded).

**Surviving attacks:** A1 — the open-`T?` deferral is evolution-safe **only because box-to-object
is already forced** by three frozen surfaces (box-collapse `Any?` convention; canonical
interface slots already carrying `T?`-as-`object`, `DotNetIlCodegenSupport.kt:405-416`; frozen
`Nullable<int32>` instantiation tokens in shipped assemblies) — the option-carrier alternative
breaks nullability collapse (`Int??` = `Int?`) across assemblies and C# cannot be forced to
normalize; **none of this is written down, and there is no nullability ADR among the 12** — the
single largest undocumented decision in the backend (HOLDS → register item 8). A2 — clash gates
degrade legal MPP Kotlin into warning-level silent API loss in library mode with no `@DotNetName`
escape hatch (HOLDS → merges into D2.1 + register items 1, 9). A4 — the reference arm has no
metadata outside exports, no boundary guards, and no recorded decision either way (HOLDS →
merges into I-1, register item 10; the freeze-deadline framing was the only overstatement —
JVM tightened guards post-hoc in 1.4).

### 4.5 Runtime floor (.NET Framework 4.8 + netstandard2.0)

**Held under attack / steelman confirmed:** the library/runtime axis split (which contract
libraries compile against vs which runtime launches the exe — the JVM `-release` analogue);
netstandard2.0 as the immutable, universally implemented library contract; Framework ILAsm as an
independent second ECMA-335 implementation that has demonstrably caught real bugs
(il-assembly ADR:64-67). Attack 5 (mixed corlib) NEUTRALIZED — recorded, and index signatures
already avoid corlib-facade identity. Attack 4 downgraded to minor — the NLS/ICU normalization
policy IS recorded (AGENTS.md:739-744); residue is one general policy bullet plus enforcement
(§1). Attack 6 downgraded to minor — the ceiling's force is carried by DIM (= attack 1) or by
features lacking Kotlin prerequisites; residue: enumerate the ceiling in the floor ADR.

**Surviving attacks:**

- **Attack 2 — the floor is a phantom decision. HOLDS (deferred-must-record).** "Runs on .NET
  Framework 4.8" is a numbered *requirement* in six ABI drafts; one ADR states it "is probe
  evidence…, not a decision about the eventual product support baseline"
  (`draft-adr-erased-callable-abi.md:497-498`); the library-profile ADR derives netstandard2.0
  *from* the floor it presupposes; **no ADR decides the floor** — no audience analysis (nothing
  in the repo names who runs new Kotlin code on Framework 4.8), no foreclosure accounting, no
  sunset criteria. The default `-Xdotnet-target=netframework` is a bootstrap convenience
  (Framework ILAsm ships with Windows) silently promoted into the deepest ABI-shaping constraint
  in the project. JVM/Native floors are explicit, versioned, publicly re-decided contracts.
- **Attack 1 — DIM foreclosure. HOLDS (questionable, escalating to architecturally-wrong if
  ABI-1 stabilizes without a recorded DIM trade study).** The floor forces the
  DefaultImpls-shaped interface plan (helper + per-class forwarder, variant ADR:557-561;
  "JVM DefaultImpls ownership without CLR DIM", `DotNetLoweringPhases.kt:87-89`), replaying the
  JVM's most regretted, best-documented ABI mistake (~9 years from ship to defaults-on, four
  incompatible modes, `AbstractMethodError` mixtures, permanent Java-implementor complaints) at
  the only moment in the target's life when avoiding it is free (zero existing binaries). The
  multi-TFM escape is self-blocked: the profile ADR forbids higher-TFM assets from changing
  identity (:53-55), and interface *shape* is identity. The mitigations do not defuse: bodies
  are still rejected; the default-arg `<DefaultImpls>` helper is already landed public metadata;
  the erased-callable ADR reserves the product floor decision. Reconciled stance for this review
  (resolving I-8 vs class-model F3 vs this attack): **netstandard2.0 as the library API profile
  is correct-direction; Framework 4.8 as an ABI-shaping veto is undecided and must not remain
  implicit.** The strongest defensible position is two-tier: Framework demoted to a conformance
  oracle + best-effort executable subset, with the interface ABI decided on modern-CLR merits —
  but the point of register item 6 is that *someone must decide*, in an ADR, against the JVM
  history. [interpretation + recommendation]
- **Attack 3 — floor evidence uncommitted. HOLDS** → consolidated in §1 (the constraint that
  vetoes DIM is itself the least-verified property of the system; silent floor rot is
  undetectable by any committed gate; the il-assembly ADR's own acceptance gate demands the full
  suite "on every supported CLR target", :93).

## 6. Conclusions — the seven required parts

### 6.1 Overall architectural verdict

This is the most disciplined compiler-backend prototype this reviewer has assessed. The
foundational representation layer — `System.Object` as `Any` with one runtime semantics
choke point, hybrid `Nullable<T>`, erased-callable identity with optional capabilities, the
split-interface identity core, CLR-native class/singleton/slot discipline, curated exception
mapping with loud rejection of everything else — is **correct in direction, internally coherent
(one erasure doctrine applied uniformly across callables, interfaces, and data-class equality),
and argued against real alternatives with instruction-level evidence**. The red teams broke none
of the five identity cores; every confirmed architecture defect is at the edges: *when* keys are
computed (D7.1, the one standing architecturally-wrong item of substance), *what freezes names*
(digest policy), *what versions the runtime surface* (capability floor), and *what the warnings
hide* (eviction in library mode). The dominant risk class is not wrong design but **unrecorded
decisions hardening by default** — 25+ deferred-must-record items — on an evidence base that is
largely outside the repository. [interpretation]

### 6.2 Strongest decisions already made

1. `System.Object` as physical `Any` + `Kotlin.Runtime.Internal.Intrinsics` normalization (D3) —
   the single most load-bearing commitment, and the correct one.
2. Hybrid `Nullable<T>` — C# sees `int?`; JVM-observable semantics restored at one choke point;
   survived every red-team semantic attack including the refuted IEEE one.
3. Erased non-generic callable identity + `isinst`-guarded optional capabilities — the correct
   CLR answer to a constraint the JVM never faces; evolvable by construction.
4. The split-interface **identity layer** (canonical erased identity, instruction-free variance,
   erased `is`/`as`) — unbroken under a dedicated adversarial pass.
5. CLR-native class model: no vtable lowering, probe-verified slot discipline,
   `beforefieldinit`-based first-active-use semantics, real properties.
6. The exception registry's method: small, curated, per-type documented, fail-loud everywhere
   else; `exceptionabi_s4` as evidence-driven refusal of the tempting shortcut.
7. Placement ownership (user / Stdlib / Runtime / intrinsics) with a proven completed migration,
   and quarantined bootstrap machinery with explicit kill events.
8. The textual-IL ADR — a model of how to record a temporary (honest, specific triggers,
   retained conformance lane).
9. Process: 12 real ADRs, probe-cited design law, exact goldens both FIR parsers share,
   an assertion-dense box corpus, cross-model adversarial review commits.

### 6.3 Most dangerous current decisions

1. **Logical ABI keys from lowered IR** (D7.1, architecturally-wrong): cross-module vararg
   linkage is silently severed today; each future shape-mutating lowering widens the hole.
2. **Mangler output as durable CLR ABI without a freeze policy** (D7.2/§4.1 A1): the first
   mangler revision after any external pair ships is an ecosystem-wide, partially source-level
   break.
3. **Fixed 1.0.0.0 runtime identity + planned additive capability growth with no floor
   mechanism** (§4.4 A1): a guaranteed future `TypeLoadException` class with no diagnostic.
4. **Warnings-only eviction reaching library artifacts** (D2.1): complete metadata over
   subset DLLs — silent transitive API rot two module-hops from the cause.
5. **The phantom Framework 4.8 floor forcing a DefaultImpls-shaped interface ABI** (§4.5):
   replaying the JVM's most regretted ABI decision, by default rather than by decision, plus the
   freeze-coupled `IEnumerable<T>` question steered away from rather than toward.
6. **The exception endgame doctrine** (D6.1): the recorded direction is unreachable, the
   alternative is unanalyzed, and CancellationException is already constrained by a frozen
   mapping nobody connected to it.
7. **Pinning provisional deltas as desired behavior** (`errorIdentity.kt` catch collapse;
   whole-file goldens): regression protection quietly converts POC expedients into semantics.

### 6.4 Foundational issues to correct before adding more language features

In dependency order: (1) register items 1-2 — eviction fenced out of library mode and key
computation moved pre-lowering, because every new feature multiplies both surfaces; (2) item 3 —
the runtime surface-level floor, before the second capability wave (which suspend forces
immediately via arity growth); (3) item 6 — the floor ADR, before any further interface ABI
accrues; (4) items 5 and 8 — the exception-endgame and nullability/`T?` decisions, because
`Map`, user exceptions, and coroutines are all downstream of them; (5) item 12's P0 half —
the two silent-pass `?: return` fixes and the first committed foreign-execution lane, because
every further feature validated only by uncommitted probes deepens §1.

### 6.5 Issues that may safely remain incomplete

Arities 4..22 (mechanically additive once item 3 exists); reflection beyond the name-only floor;
`kotlin-reflect`-class metadata; the direct PE writer (ADR-scheduled; text+ILAsm is fine
meanwhile); Unit typed capabilities and TypedArguments arity-3 (benchmark-gated by their own
ADR); interface *default-argument* dispatchers (already correctly shaped); `IEnumerable`
*adapters* (only the same-object identity question is freeze-coupled); companion-of-generic
implementation (exit nearly forced; record only); stack-trace/suppressed surfacing (additive
runtime types under ABI-1 practice); K1 support (never; record one sentence); KGP/build
integration; the option of embedding metadata in the DLL (decide, implement later); enum/value
class/lateinit/annotation/concurrency implementations — provided §3's design notes park them
explicitly rather than by omission.

### 6.6 Prioritized roadmap

- **Now (days):** fix the two `?: return` silent passes; error-on-eviction in library/stdlib
  modes; the two-line stack-merge check; extract and upstream the two shared-IR fixes;
  correct the stale user-exception message and the drift sentence.
- **Next (weeks) — P0 register:** pre-lowering key computation + frozen-fixture skew test;
  name-freeze/digest ADR; runtime surface-level floor; reference-equality id on public
  signatures; exception-endgame decision unit (filter probes + CancellationException);
  runtime-floor ADR (DIM trade study); variant-ADR revision (IEnumerable, placement freeze,
  two-view pricing, barrier contract, clash-gate pins); nullability ADR.
- **Then (1-2 months) — P1:** evidence lanes (Framework execution, Roslyn consumer, ilverify,
  skew CLI golden, assemble-all-goldens); KLIB↔DLL content hash; export posture (guards +
  marker attributes); session factory + checker migration begins; runtime-IL strata record;
  AGENTS normative split + ADR promotion; `BuiltInsPlatform` request upstream.
- **Before any stability claim — P2:** diagnostics migration to `IrDiagnosticReporter`/FIR
  checkers; golden restructure + `MODULE:` box + corpus scaling; dotnet-owned test module;
  single-artifact decision; §3 design notes for enums/value classes/coroutines/concurrency.

### 6.7 Maturity assessment: prototype vs viable experimental backend vs credible future official target

**Today it is a high-quality prototype at the upper boundary of that class — and it is a
credible *candidate* for an official target, which is a statement about trajectory, not
status.** [interpretation]

- It is more than a throwaway prototype: the representation core is production-shaped, the
  decision hygiene (ADRs, probes, goldens, adversarial review) exceeds most experimental
  backends, and no foundational layer needs reversal.
- It is **not yet a viable experimental backend** in the sense of something third parties could
  build against, because the four P0 mechanical items (eviction-in-library, key asymmetry,
  name freeze, runtime floor) make any shipped pair a liability, and because the validation
  story is unreproducible outside one machine (§1).
- The path to **credible future official target** is genuinely open: none of the confirmed
  defects is load-bearing architecture, all have identified mechanical fixes, and the two
  decisions that would be genuinely hard to unwind later — the interface-ABI floor and the
  exception endgame — are precisely the ones this review requires to be decided on the record
  before freeze. If the P0 register lands and the evidence base converts to committed lanes,
  the remaining distance to "official experimental target" is stdlib breadth, frontend
  ownership (session factory + checkers), and build-system integration — labor, not risk.
  If instead ABI-1 freezes first, the project will have converted its best asset (a clean
  slate) into the JVM's two most expensive legacies (DefaultImpls and unversioned mangled
  names), knowingly. [interpretation + recommendation]
